# Task 04 — Uluslararasılaştırma (i18n): TR/EN

## Amaç
Assos yabancı turist çeken bir bölge; site şu an %100 Türkçe (`lang="tr"`, dil seçici yok, hreflang yok). `next-intl` ile tam TR/EN desteği kurulacak. TR varsayılan dil olarak URL öneki olmadan kalır (`/`), İngilizce `/en/...` altında yaşar.

## UYARI — en invaziv task
Bu task neredeyse tüm sayfa ve bileşenlere dokunur. Dalga 2'de, Task 02 ve 06 merge edildikten SONRA başla. Task 03 ile paralel çalışıyorsan 03'ün yeni sayfaları (kvkk, gizlilik, iptal) merge edildikten sonra bir "string extraction final pass" yap.

## Dokunulacak dosyalar
- YENİ: `src/i18n/{routing.ts,request.ts}`, `messages/tr.json`, `messages/en.json`
- `src/proxy.ts` (next-intl middleware ile birleştirme — DİKKAT: mevcut admin koruması bozulmamalı)
- `src/app/layout.tsx`, `src/app/(public)/**` → `src/app/[locale]/(public)/**` yeniden yapılandırması
- Tüm `src/components/**` (string extraction)
- `src/components/layout/navbar.tsx` (dil seçici)
- `src/app/sitemap.ts` (hreflang alternates)
- `src/lib/mail/templates.ts` (iki dilli e-posta)

## Adımlar

### 1. Altyapı
- `npm i next-intl`. `defineRouting({ locales: ['tr','en'], defaultLocale: 'tr', localePrefix: 'as-needed' })` → TR URL'leri değişmez (SEO korunur), EN `/en` önekli.
- App Router yapısını `src/app/[locale]/...` altına taşı. **Admin ve API route'ları locale dışında bırak** (`src/app/admin`, `src/app/api` yerinde kalır).
- `src/proxy.ts`: next-intl middleware'ini mevcut admin session korumasıyla tek middleware'de zincirle. Matcher'ı güncelle; `/admin` ve `/api` yollarının intl middleware'ine GİRMEDİĞİNİ test et.

### 2. String extraction
- Tüm kullanıcıya görünen metinleri `messages/tr.json`'a namespace'li taşı (`home.hero.title`, `booking.form.email` ...). Bileşenlerde `useTranslations` / server'da `getTranslations`.
- API hata mesajları: route'lar `Accept-Language` yerine istekle gelen `locale` alanına göre mesaj seçsin; pratik çözüm — hata KODU döndür (`"errors.noAvailability"`), client tarafında çevir. Zod hata mesajlarını da koda çevir.
- `messages/en.json`: profesyonel otelcilik İngilizcesi ile çevir ("Deluxe Full Sea View", "Book now, pay later" DEĞİL — kapora modeli doğru anlatılmalı: "reservation is confirmed after deposit payment"). Pazarlama metinlerinde birebir çeviri değil, doğal transcreation.

### 3. Dil seçici ve biçimlendirme
- Navbar'a minimal TR/EN switcher (mevcut path'i koruyarak locale değiştirir).
- Tarih biçimleri `date-fns` locale'leriyle (`tr`, `enUS`); para birimi: EN tarafında TRY fiyatın yanında yaklaşık EUR göster (`~€215`) — kur değeri `src/lib/config/hotel.ts`'e elle girilen `EUR_RATE` sabiti + "approx." ibaresi (canlı kur API'si KURMA, scope dışı).
- `html lang` dinamik; `metadata` (title/description) her iki dilde; OpenGraph locale alternates.

### 4. E-postalar
- Rezervasyon formundan locale'i payload'a ekle; misafir e-postaları seçilen dilde gitsin (template'leri `tr`/`en` varyantlı yap). Admin bildirimleri her zaman TR.

### 5. SEO entegrasyonu
- `sitemap.ts`: her URL için `alternates.languages` (hreflang) çıktısı.
- Task 06'nın JSON-LD bileşeni locale-aware `description` alsın (koordinasyon: JSON-LD bileşenine `locale` prop'u ekle).

## Yapma (scope dışı)
- Üçüncü dil ekleme.
- Canlı döviz kuru servisi.
- Admin panelini çevirme (TR kalır).

## Kabul kriterleri
- `/` ve `/en` her sayfa için çalışır; TR URL'leri DEĞİŞMEMİŞTİR (eski linkler kırılmaz).
- `/admin` ve `/api/**` davranışı i18n öncesiyle birebir aynı (login yönlendirmesi dahil — regresyon testi yap).
- Kaynakta hard-coded Türkçe kullanıcı metni kalmaz (`grep` ile örneklem kontrolü).
- EN sayfada rezervasyon uçtan uca tamamlanır ve misafir e-postası İngilizce gider.
- hreflang etiketleri `<head>`'de ve sitemap'te doğrulanır.
- `npm run build` yeşil.
